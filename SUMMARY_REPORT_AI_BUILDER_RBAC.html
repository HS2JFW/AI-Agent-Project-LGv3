ในระหว่างกระบวนการ Deploy ได้มีการแก้ไขปัญหาทางเทคนิคสำคัญเพื่อความเสถียรของระบบ:

  • การแก้ปัญหา Port Collision กับ Traefik Reverse Proxy: ใน Coolify มี Traefik ผูกพอร์ต 80 และ 443 ไว้อยู่แล้ว จึงปรับปรุงไฟล์ docker-compose.yml ของแอปพลิเคชัน จากเดิมที่ใช้ ports: ["80:80"] ให้เปลี่ยนเป็น expose: ["80"] เพื่อส่งมอบทราฟฟิกให้ Traefik จัดการ Forward เข้าสู่คอนเทนเนอร์ได้อย่างถูกต้อง 100%
  • การคอนฟิก Routing Domain อัตโนมัติ: กำหนดค่า docker_compose_domains ให้กับบริการ frontend ชี้ไปยัง https://aibuilder-dev.addpay.in.th พร้อมระบบ SSL/TLS อัตโนมัติ

3. โครงสร้างและสิทธิ์ของระบบ RBAC (5-Tier Role Matrix)

ระบบได้รับการออกแบบให้แบ่งแยกหน้าที่อย่างชัดเจน (Separation of Concerns) ตามหลักการรักษาความปลอดภัยของระบบประมวลผล AI:

บทบาท (Role) ระดับสิทธิ์ หน้าที่ความรับผิดชอบ ข้อจำกัด (Restrictions)
superadmin Tier 1 (สูงสุด) ผู้ดูแลระบบสูงสุด จัดการบัญชีผู้ใช้ทั้งหมด, กำหนด Policy ระบบ, ดูแลและลบ Workflow ได้ทุกตัว ไม่มี (สิทธิ์สมบูรณ์)
admin Tier 2 ผู้จัดการระบบ สามารถเข้าเมนู User Management, ดูแล Workflow ในภาพรวม และตั้งค่าระบบ ไม่สามารถยกระดับตนเองเป็น Superadmin ได้
builder Tier 3 ผู้สร้าง Workflow ออกแบบและแก้ไข Node Canvas, กำหนด Logic, Prompt และทดสอบ Flow ของตนเอง ไม่สามารถแก้ไขหรือลบ Workflow ของผู้อื่นได้ และไม่เห็นเมนูจัดการผู้ใช้
operator Tier 4 เจ้าหน้าที่ปฏิบัติการ ส่งไฟล์เอกสาร (PDF, CSV) เข้าคิวประมวลผล สั่งเริ่มรัน Workflow และรับผลลัพธ์ ห้ามสร้าง, แก้ไข หรือลบโครงสร้าง Node ใน Workflow โดยเด็ดขาด
viewer Tier 5 (Read-only) ผู้ตรวจสอบหรือผู้บริหาร เปิดดูผัง Workflow และประวัติการทำงานเพื่อการตรวจสอบ/รายงาน เปิดดูได้อย่างเดียว ห้ามสั่งรัน, ห้ามบันทึก และห้ามแก้ไขใดๆ ทั้งสิ้น

4. การพัฒนาฝั่ง Backend (FastAPI + SQLAlchemy + SQLite)

4.1 การปรับปรุง Database Model & Auto-Migration Mechanism

ในระบบเดิมตาราง users และ workflows ยังไม่มีโครงสร้างรองรับชื่อ-แผนก และเจ้าของข้อมูล เพื่อป้องกันปัญหาข้อมูลสูญหายจากการ Drop Table บน Production ทางทีมงานได้พัฒนาระบบ Auto-Migration ในไฟล์ database.py ที่ทำงานตรวจสอบ Schema อัตโนมัติในตอนเปิดเครื่อง:

  • เพิ่มคอลัมน์ full_name VARCHAR(255), department VARCHAR(100), last_login_at DATETIME ในตาราง users
  • เพิ่มคอลัมน์ owner_id VARCHAR(36) และ is_public BOOLEAN DEFAULT 1 ในตาราง workflows
  • สร้าง Seed Data ผู้ใช้งานเริ่มต้น 5 ระดับสิทธิ์อัตโนมัติหากยังไม่มีในฐานข้อมูล

4.2 Security Guards & Access Dependencies

สร้าง Dependency ฟังก์ชันสำหรับคุ้มครอง API ในไฟล์ auth.py:

  • require_role(*allowed_roles): สกัดกั้นผู้ใช้งานที่มี Role ไม่ตรงตามเงื่อนไข ตอบกลับ 403 Forbidden ทันทีในระดับ Kernel
  • get_current_active_user_optional: ตรวจสอบสิทธิ์แบบ Soft-Auth สำหรับ Endpoint ที่รองรับทั้งการเรียกดูแบบ Public และการแสดงผลส่วนบุคคล

4.3 ชุด User Management API (/api/users)

  • GET /api/users/roles: ดึงรายชื่อ Role ทั้งหมดพร้อมคำอธิบาย (Public)
  • GET /api/users: ดึงรายชื่อผู้ใช้ทั้งหมด (อนุญาตเฉพาะ superadmin, admin)
  • POST /api/users: สร้างบัญชีผู้ใช้งานใหม่ กำหนดรหัสผ่านเริ่มต้น และเลือก Role
  • PATCH /api/users/{id}: แก้ไขข้อมูลผู้ใช้ ปรับ Role รีเซ็ตรหัสผ่าน หรือเปิด/ปิดบัญชี
  • DELETE /api/users/{id}: ลบบัญชีผู้ใช้ (มีระบบป้องกันไม่ให้ลบบัญชีตนเอง)
